The Rise of Autonomous AI Coding Agents

As software development transitions into an era of autonomous coding agents, developer tooling must adapt. To understand ecosystem adoption, quantify automated code generation, and tailor developer experiences, the official GitLab CLI (glab) tracks agent invocations through its DetectCodingAgent() engine.

However, the rapid influx of new agent runtimes created notable telemetry gaps and attribution conflicts. In Issue #8749, we set out to build an accurate, battle-tested detection engine capable of distinguishing between dozens of concurrent agent environments.

The Telemetry Blindspots & Precedence Challenges

Detecting an agent is not as simple as checking whether an environment variable exists. Real-world development setups introduce intricate layering:

  • Subshell Inheritance & Forwarding: Amp wraps Claude Code underneath, setting both AMP_CURRENT_THREAD_ID and CLAUDECODE=1. Checking Claude Code first resulted in false attribution.
  • Fork Ecosystems: Kilo Code runs as a fork of OpenCode, setting both KILO=1 and OPENCODE=1.
  • Legacy Variables: Tools utilizing legacy AGENT variables instead of standard AI_AGENT were completely ignored.
  • Missed Modern Agents: Emerging agents such as Google Antigravity, Amazon Q Developer CLI, Augment, Cline, Goose, JetBrains Junie, Qwen Code, Trae, and Warp possessed zero detection markers.

The Architectural Solution in MR !4459

In Merge Request !4459, we overhauled internal/api/coding_agent.go:

1. Robust Precedence Chains

// Precedence: Amp runs Claude Code underneath, so check Amp first
if os.Getenv("AMP_CURRENT_THREAD_ID") != "" {
    return "amp"
}
if os.Getenv("CLAUDECODE") == "1" {
    return "claude-code"
}

// Kilo wraps OpenCode, so check Kilo first
if os.Getenv("KILO") == "1" {
    return "kilo"
}
if os.Getenv("OPENCODE") == "1" {
    return "opencode"
}

2. Expanded Signatures

We incorporated precise signatures for newly adopted industry agents:

  • ANTIGRAVITY_AGENT → "antigravity"
  • AWS_EXECUTION_ENV matching AmazonQ-For-CLI → "amazon-q"
  • AUGMENT_AGENT=1 → "augment"
  • CLINE_ACTIVE=true → "cline"
  • GOOSE_TERMINAL=1 → "goose"
  • JUNIE_SHIM_PATH → "junie"
  • QWEN_CODE=1 → "qwen-code"
  • TRAE_AI_SHELL_ID → "trae"
  • OZ_RUN_ID → "warp"

Key Takeaways for Tool Developers

  • Hierarchical Awareness: Never assume agent environments are mutually exclusive. Always evaluate child or wrapper tools prior to parent runtimes.
  • Strict Sanitization: Fallback variables must be validated against token regexes to reject invalid boolean flags like 1 or true.
  • Hermetic Test Cleansing: Test suites evaluating process environment variables must scrub all potential candidate variables to avoid flaky test executions across diverse CI runner environments.
