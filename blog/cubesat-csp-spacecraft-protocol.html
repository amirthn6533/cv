Addresses embedded telemetry and USART driver stability in EnduroSat's specialized CubeSat Space Protocol implementation.

The CubeSat Space Protocol (CSP) in Orbit

The CubeSat Space Protocol (CSP) is the de facto networking standard for nanosatellites and orbital hardware modules. EnduroSat maintains csp-es, an optimized fork tailored to high-throughput satellite constellations, inter-subsystem buses, and ground station telemetry.

The Challenge of Desktop-to-Orbit Simulation

Spacecraft firmware is tested on desktop developer workstations via Hardware-in-the-Loop (HIL) simulators and serial bridges before flashing to flight microcontrollers. During Windows/MinGW builds, two critical obstacles arose:

  1. POSIX Timer Redefinitions: In src/arch/windows/csp_time.c, an unconditional fallback implementation of clock_gettime conflicted with the native declaration in MinGW winpthreads headers: 
    error: redefinition of 'clock_gettime'
  2. Silent USART Crash: In src/drivers/usart/usart_windows.c, thread spawning passed a NULL parameter rather than the driver context structure: 
    // Prior bug: lpParameter was NULL!
(HANDLE)_beginthreadex(NULL, 0, usart_rx_thread, NULL, 0, &th_id);
    When the worker thread launched, it immediately dereferenced ctx->fd, triggering an access violation and leaking hardware handles.

The Architecture Fix

In PR #2, we guarded the clock implementation with #ifndef _POSIX_TIMERS to preserve cross-compiler compatibility between MSVC and MinGW-w64. Furthermore, we routed the valid ctx pointer to _beginthreadex, added error-checking to return CSP_ERR_DRIVER on thread launch failure, and sanitized handle lifecycles.

This allows engineers to compile and simulate spacecraft communication stacks locally with zero friction, expediting orbital software testing cycles.
