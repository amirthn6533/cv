Standardizing Numerical Resource ID Validation Across 25 Go CLI Packages

Author: Amir Tahani
Target: gitlab-org/cli
Merge Request: MR !4425
Reading Time: 6 min read
GitLab CLI Merge Request !4425: refactor(cmdutils): share ParseID helper so invalid-ID errors name rejected value →

Approved by GitLab maintainer Rane Hebden. Unifies ID parsing across 25 packages, eliminates opaque strconv errors, and enforces strict positive identifier validation.

The Ergonomic Flaw in Command-Line Error Messages

In command-line tools managing complex remote infrastructure (such as GitLab Runners, Container Registries, and Deploy Tokens), user input errors should clearly reflect what was typed wrong. Previously, when users entered non-numeric IDs like glab runner get abc, the output was: 

strconv.ParseInt: parsing "abc": invalid syntax

While engineers had attempted to wrap this via cmdutils.WrapError(err, "invalid runner ID"), the underlying ExitError discarded the descriptive wrapper string during console output, yielding unhelpful, robotic errors.

The Unified Helper: cmdutils.ParseID

In Merge Request !4425, we introduced a centralized parsing and validation utility: 

func ParseID(value, name string) (int64, error) {
    id, err := strconv.ParseInt(value, 10, 64)
    if err != nil || id < 1 {
        return 0, fmt.Errorf("invalid %s: %q", name, value)
    }
    return id, nil
}

Key Enhancements:

  • Rejecting Zero & Negative IDs: GitLab database IDs are guaranteed to be positive integers (>= 1). Rejecting 0 or -1 client-side prevents redundant HTTP network roundtrips.
  • Clear User Feedback: Errors precisely state the entity and the rejected literal value: invalid runner controller ID: "foo".
  • Broad Migration: Refactored 25 packages across runner, runnercontroller, container_registry, and deploy-token.

Maintainer Verification & Approval

Following extensive table-driven test additions to verify isolated subtest executions, GitLab CLI Maintainer Rane Hebden reviewed and approved the change:

💬 Maintainer Review Summary

"I checked that every call site that now rejects 0 and negative values parses a positional GitLab resource ID, which GitLab never issues below 1, so the stricter check can't refuse a real ID... Merged into current main, the 25 touched packages pass go test and golangci-lint reports 0 issues. Approving."

Conclusion

Consolidating repetitive parsing patterns into well-tested utility primitives drastically reduces boilerplate while enforcing a high standard of consistency across enterprise CLI suites.
