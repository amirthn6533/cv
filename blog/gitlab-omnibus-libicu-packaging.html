Robust Package Version Derivation in GitLab Omnibus Build Pipelines

Omnibus GitLab Merge Request !10101: Deduplicate libicu version derivation in config/software/libicu.rb →

Fixes Issue #10220. Replaces split-brain version parsing with a single source of truth supporting both legacy and modern ICU tag formats.

The Challenge of C/C++ Dependency Management in Linux Distributions

Omnibus GitLab packages all required runtime binaries—PostgreSQL, Redis, Gitaly, Ruby, and foundational C libraries like libicu (International Components for Unicode)—into self-contained deb/rpm distributions.

In config/software/libicu.rb, the build definition had diverged in how it derived version strings:

  • display_version used one string mutation approach.
  • The installation script creating the embedded/share/icu/current symlink implemented a completely separate, ad-hoc string replacement.

The Fragility of Dual Implementations

Upstream ICU changed their tag conventions over time:

  • Legacy tags: release-63-1 → requires replacing hyphens with dots: 63.1.
  • Modern tags: release-78.3 → already contains dots.

When version updates occurred, the symlink logic failed to match the actual installed directory name, breaking internationalization libraries during omnibus container initialization.

The Solution: Single Source of Truth

In Merge Request !10101, we established an immutable canonical version derivation: 

plain_version = version.print(false).delete_prefix('release-').tr('-', '.')
display_version plain_version

# Reused directly in link creation
link "#{install_dir}/embedded/share/icu/#{plain_version}",
     "#{install_dir}/embedded/share/icu/current"

This unified approach cleanly normalizes both hyphenated and dotted tags, eliminating split-brain defects and guaranteeing reliable symlink construction across all Linux architecture targets.
